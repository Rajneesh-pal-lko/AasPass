# AasPass — Complete Project Summary

---

## What Is AasPass?
A **WhatsApp-native cab splitting platform**. No app download. Users discover it via Instagram ads, open WhatsApp, and a bot matches them with fellow passengers on the same flight heading to the same area — so they can split a cab and save money.

**First market:** Hyderabad Airport (70,000 daily passengers)

---

## How It Works (User Journey)

```
User sees Instagram ad at airport
        ↓
Taps ad → opens WhatsApp → sends "hi"
        ↓
Bot asks: Which city? (Hyderabad / Bangalore / Delhi)
        ↓
Bot asks: Share your location (confirms they're at airport)
        ↓
Bot asks: Flight number? (e.g. 6E-204)
        ↓
Bot asks: Arrival time? (e.g. 16:45)
        ↓
Bot asks: Drop location? (share pin)
        ↓
Bot shows summary → user confirms
        ↓
Server searches for matches (same flight + drop within 5km)
        ↓
If match found → shows ranked list → user picks one
        ↓
Other person gets Accept/Decline request
        ↓
If accepted → User A pays ₹1 via Razorpay
        ↓
Both get each other's WhatsApp numbers
        ↓
They meet at Arrivals, split an Uber 50/50
        ↓
Bot asks: Did it work? → Done / Issue
```

## State Machine (User States)

```
IDLE
  → sends "hi"
ONBOARDING_CITY
  → picks city
ONBOARDING_LOCATION
  → shares airport location
ONBOARDING_FLIGHT
  → types flight number
ONBOARDING_ARRIVAL
  → types arrival time
ONBOARDING_DROP
  → shares drop pin
ONBOARDING_CONFIRM
  → confirms details
WAITING
  → sends match request
MATCH_SENT         → (declined/expired) → WAITING
  → other accepts
MATCH_RECEIVED     → (declines) → WAITING
  → accepts
MATCHED            → (cancel) → WAITING
  → says DONE
COMPLETED
```

## Database Tables (Supabase)

**users** — every person who onboards
```
user_id, phone, flight_number, arrival_time,
departure_airport, departure_lat, departure_long,
drop_zone, drop_lat, drop_long,
state, is_matched, is_active, payment_verified,
matched_with, pending_request_id,
created_at, updated_at
```

**match_requests** — every match attempt
```
request_id, from_user, to_user, distance_km,
status (pending/accepted/declined/cancelled/expired/completed),
cancelled_by, cancelled_at, confirmed_by, confirmed_at,
issue_reported, created_at, responded_at
```

**confirmed_matches** — successful pairs
```
match_id, user_a, user_b, flight_number,
distance_km, confirmed_at
```

**support_queue** — reported issues
```
issue_id, user_id, match_id, issue_type,
description, created_at, resolved
```

| `MATCHES` | View available matches |
| `CANCEL` | Cancel request or match |
| `CONFIRM CANCEL` | Confirm cancellation |
| `BACK` | Keep current match |
| `DONE` | Trip completed |
| `ISSUE` | Report a problem |
| `STATUS` | Check current state |
| `RESTART` | Start fresh |
| `STOP` | Unsubscribe |
| `HELP` | Show all commands |

## Matching Logic

- Finds users with the **same flight number**
- Who are **active + unmatched**
- Whose drop pin is **within 5km** of yours
- Sorts by **closest distance first**
- Match request **expires in 10 minutes** if no response
- User spots **expire after 2 hours** in waiting pool (cron job runs every 10 min)
